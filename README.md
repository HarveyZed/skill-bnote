# bnote

输入是一个 B 站视频链接（BV 号或 URL，可以带分 P），产出是按原时间轴逐节拆开的 Markdown 讲义 `lecture.md` 与单课笔记 `note.md`。
讲义里每一节都配上那一页幻灯片的终态帧，正文以页面上的文字和讲师原话为准，口播类视频则产出一份不做摘要的整理稿。
和只吃字幕的工具最大的不同是：bnote 连画面一起处理——抽帧、切片、选终态帧、OCR、再把图归属到对应小节——并且用校验拦住“把课程压成摘要”。

## 它解决什么问题

- 跟着一套 20 讲的课程做项目，两周后要回忆“当时那一页的参数是什么”，只能拖着进度条来回找。
- 想省事，把课程丢给 AI 做总结：例子和参数被压没了，页面上那张表也不见了，剩下的概括看着通顺，反而不敢照着做。
- 字幕记的是“讲师在说什么”，不记“这一页写着什么”——公式、参数表、代码都在画面上，字幕里一句都没有。

bnote 把这类视频做成一份和原视频对得上的 Markdown：按原时间轴逐节拆开，每节配这一页的幻灯片图，正文以页面文字与讲师原话为准。复习时翻讲义，要核对就点回那一节。

## 和同类项目比，差别在哪

同为“视频 → 笔记”，产物形态不同：下表的项目产出的是一份压缩过的笔记或报告（按提示词或字数预算写出概括），bnote 产出的是按原时间轴切分、每节对应一页幻灯片的逐节讲义。

| 项目 | 输入 | 产物 | 画面怎么处理 |
|---|---|---|---|
| [video-to-notes](https://github.com/KIRVO-REPORTING/video-to-notes) | YouTube / B 站 / TED 等 yt-dlp 支持的链接 | 带时间戳的报告、摘要、可搜索的本地 dashboard | 只吃字幕，不抽帧 |
| [bili-note](https://github.com/Rimagination/bili-note) | B 站视频与图文动态 | 归档字幕、图文正文与评论的知识库 Markdown | 只归档图文里的图片，视频画面不处理 |
| [BiliSum](https://github.com/lycohana/BiliSum) | B 站 / YouTube / 本地视频文件 | 转写 → 文本笔记 → 图文笔记 → 思维导图 | 视觉模型读截图并精选配图，图片跟随知识段落 |
| [AI-Media2Doc](https://github.com/hanshuaikang/AI-Media2Doc) | 视频 / 音频 | 公众号 / 知识笔记 / 思维导图等风格的文档 | 按字幕时间点截图，不做画面稳定性分析 |

差别最大的地方是画面这一路：抽帧 → 找到画面稳定下来的区间并切片 → 在每段里挑出这一页的终态帧 → OCR 页面文字 → 把图归属到对应小节。以上依据各项目 README 自述，若与实际不符欢迎提 issue 更正。

## 它能做什么

- **两类视频分别处理**：幻灯片课走完整流水线（抽帧 → 切片 → OCR → 分章 → 逐节写作）；口播、播客、访谈走信息流模式（不抽帧、不分章，字幕按语义分段后逐块整理）。
- **配的是“一页讲完了”的那一帧**：按帧差找到画面稳定下来的区间，再从每段的候选帧里按墨迹、清晰度与 OCR 文字量挑出终态帧；同一页的不同阶段能合并，真换页不会混。
- **不摘要、不编造**：整理稿正文有下限（低于字幕正文的 0.85 直接判错）；“覆盖每个知识点、图注必须自己打开图看过、不编造”写在随任务书下发的写作契约里，由扮演写手的 agent 逐条遵守。
- **产物是纯 Markdown，可以直接进知识库**：图片用相对路径引用，整份 `out/<vid>/` 复制进 Obsidian / Notion 一类工具即可；另有图片内嵌的 `lecture.standalone.md`，适合直接外发分享。
- **能把讲义贴回 B 站笔记**：`export` 把讲义的小节（或笔记的节点）导成笔记编辑器认得的富文本——每节一行小节标题 + 一个灰色圆角的时间标签，点一下跳到视频那一刻。走剪贴板通道而非平台写接口，Windows 上一条命令装载，详见 `references/export.md`。
- **结构由工具强校验，失败不覆盖成品**：章界、小节时间行（格式 / 单调 / 不重叠 / 越界）、幻灯片归属、图是否存在逐条校验，每条错误都带责任人路由；时间行这类派生数据由工具生成，扮演写手的 agent 不手写时间。
- **把作者自己写的说明一起带上**：取数时收下视频简介、标签、分区与 **UP 主置顶评论**，写进 `meta.json`、出现在 `index.md`、并作为背景注入派单 prompt。作者的资料链接、勘误、答疑常常只补在置顶评论里（**改简介等于重新发布视频**，所以他们更愿意动置顶评论）。为把请求压到最小，工具**只取作者置顶的那一条**，不做评论区批量采集。

## 依赖与环境

| 类别 | 要求 | 说明 |
|---|---|---|
| Python | >= 3.10 | 建议独立 venv；必备依赖（yt-dlp、numpy、Pillow、requests）由安装脚本装 |
| ffmpeg | 建议装系统版 | Linux `apt install ffmpeg`；macOS `brew install ffmpeg`。`--sections`、HLS、音视频合并需要能解析域名的 ffmpeg，`imageio-ffmpeg` 的静态包只作兜底 |
| 可选能力 | `pip install -e ".[asr,ocr]"` | `[asr]` 本地语音识别；`[ocr]` 判断“这页文字全不全” |
| 平台 | Linux / macOS | 入口与安装脚本是 bash；Windows 请在 WSL2 下使用 |

## 安装 📦

```bash
git clone https://github.com/HarveyZed/skill-bnote.git && cd skill-bnote
bash scripts/setup-env.sh      # 建 venv + 装依赖（默认清华镜像，PIP_INDEX_URL 可覆盖）
scripts/bnote auth status      # 官方字幕轨需要登录态：没有就 auth login 扫码
```

作为 agent skill 使用时，把本目录整体复制到你的 skill 根目录即可；venv 与 ffmpeg 不随 skill 走，换机器各跑一次上面的命令。

harness 需要提供两样东西：一个全新上下文的子代理（**写作由它扮演的“写手”完成，全程是 agent 在执行**），以及一个能唤醒它的消息工具。判别与替代方案见 [`references/dsh-notes.md`](references/dsh-notes.md)。

## 快速开始 🚀

```bash
# 幻灯片课：只取片头 5 分钟，验证 下载 → 字幕 → 抽帧 → 切片 → OCR → 交付
scripts/bnote run <URL> --page 1 --sections 00:00:00-00:05:00

# 口播 / 播客：分段分块 → 子代理（agent 写手）逐块写 → 拼接 → 校验
scripts/bnote stream <URL> --page 1 --sections 00:00:00-00:05:00
scripts/bnote stream <URL> --page 1 --assemble
```

跑不通时先看命令开头那行 `[paths]`（数据根是否解析到预期位置），再看 `<数据根>/out/<vid>/_meta/validation.json`。

## 怎么用

完整流程、两道门禁、派单与派修的编排方式写在 [`SKILL.md`](SKILL.md)——那份是给 agent 的执行手册，本文件只讲它是什么、值不值得用。

- **幻灯片课**：`run` 取数 → `scaffold` 分章 → 术语表评审 → `brief` 把任务书派给子代理（agent 写手）逐章写 → `collect`/`retime` 汇总时间行 → `check` 结构校验 → `merge` 出讲义与笔记。
- **口播 / 播客**：`stream` 取音频与字幕、分段分块 → 子代理（agent 写手）按块读写 → `--assemble` 拼成整理稿并校验。
- **贴回 B 站笔记**：`scripts/bnote export <URL> --page N --format bili-note` 导出可直接粘贴进 B 站笔记的富文本（时间标签可点击跳转），Windows 上用 `bili_note_clip.ps1` 装进剪贴板再 Ctrl+V。
- **配置**：全部参数与默认值见 [`references/params.md`](references/params.md)；覆盖顺序是环境变量 `BN_<段>_<键>` > `config/local.toml` > `config/default.toml`。

## 数据与目录

```
<数据根>/
  state/          跨集沉淀：术语表、内容画像、登录态（删 cache 不带走）
  cache/<vid>/    中间产物：媒体、帧、OCR、切片结果（可随时删）
  out/<vid>/      交付物：lecture.md / note.md / transcript.md / slides/ / chapters/ / _meta/
```

`<vid>` = `<BV号>_p<分P>`。数据根按 `BNOTE_ROOT` > `config/local.toml` 的 `[paths] root` > `<当前工作目录>/.bnote` 解析，每条命令都会打印解析结果；数据根必须可写，skill 根不必可写。换数据根等于换一整套 `state/`，登录态也跟着走。

## 已知限制

1. **官方字幕轨只认中文与英文**：B 站 AI 轨的匹配顺序是 `ai-zh` / `zh-Hans` / `zh-CN` / `zh` / `en`，日语、韩语等其它语种的课程拿不到官方轨。
2. **本地语音识别默认按中文识别**：语言参数默认 `zh`，没有针对其它语言做过适配或验证，日语、韩语等课程属于未验证范围。默认模型 `medium` 本身是多语种模型，改语言参数理论上可行，但没有验证过。
3. **登录态是硬门槛**：字幕轨的列表只对登录态返回，游客请求得到空列表。取不到字幕时有三条路：扫码登录、自带 srt（`--subtitle-backends file`）、本地语音识别。
4. **输入只支持 B 站链接**：BV 号或视频 URL，可以带 `p=` 分 P；**不接受本地视频文件**，也不支持其它平台，对应路线图里的“输入来源扩展”。
5. **字幕是证据，不是准绳**：平台 AI 轨与 UP 上传的 CC 都是语音识别产物、都可能没有校对。幻灯片模式以页面图上的文字为准，信息流模式以人写的元信息（标题 / 简介 / 标签 / 置顶评论）优先；拿不准就地括注存疑。
6. **置顶评论只取一条，且受平台风控影响**：只取作者置顶的那一条，不做评论区批量采集（那属于另一个量级的行为，本项目不做）。取它需要在同一次会话里先请求一次视频页拿到 `buvid3`，否则评论接口会被挡回 HTTP 412；失败不阻塞取数，只是少了这段背景。不需要登录态；不想要这两次请求就把 `meta.top_comment` 设为 `false`。**这条依赖平台的上游接口，上游改版或风控加强时可能取不到**——这是软失败（日志一行、取数照常），不是本地故障，也不是使用者能控制的。
7. **画面本身没有信息量的视频不适合幻灯片模式**：纯人像或纯动画时，“画面长时间不变 = 一页”会把静止镜头当成页，这类内容应走信息流模式。
8. **一次只处理一个分 P**：合集批量需要外层循环；相邻分 P 的接缝处可能有一段重复内容。
9. **Windows / macOS 未实机验证**：只在 Linux 上跑过，这两个平台上的安装与运行可能报错（Windows 请用 WSL2）；干净 clone 后的首次安装也没有做过端到端验证。

## 路线图 🗺️

两个方向：让画面这一路从“挑出一页的终态帧”走到“先看懂这一帧是什么”，再把输入与输出打开——输入从 B 站链接扩到本地文件与其它平台，输出从本地 Markdown 扩到能粘进 B 站笔记的富文本。前者决定讲义里的图是不是总对应整页，后者决定这门课的视频能不能进得来、整理好的讲义能不能回到课程所在的地方。

| 方向 | 计划 | 解决什么 | 受益者 |
|---|---|---|---|
| 画面理解 | 帧角色分类（整页 / 页内放大截图 / 出镜 / 插播 / 黑场），终态选帧改为“整页优先” | 讲师放大讲页内截图时，讲义存的是截图那一帧，完整页面反而丢掉 | 所有用幻灯片模式的人 |
| 画面理解 | 手写笔迹与印刷体判别，把笔迹从 OCR 输入与帧差里剥离 | 板书与圈画被读成字符，同一页因此被切成好几页 | 板书、手写批注多的课程 |
| 输入来源 | 抽出来源层（把“B 站”从隐含前提变成可替换接口）、加 yt-dlp 字幕后端、用 ffprobe 取时长 | 本地视频文件与其它平台进不来（限制 4） | 课程不在 B 站、手上只有本地录屏的人 |
| 输出形态 | 导出成可直接粘贴进 B 站笔记的富文本（每节一个可跳转的时间锚点）——**0.9.0 已实现**；后续：其它平台的装载脚本、一次粘贴几十个锚点的健壮性 | 讲义只能留在本地，B 站笔记里仍要手动记时间点 | 想在 B 站笔记里留存或分享整理结果的人 |

想认领其中某一项：在 Issues 里说明你的课程场景与视频特征，改动范围通常能收敛到一层。
## 参与与反馈 💬

- 遇到问题、跑不出结果、发现文档与实际行为不一致：到 [Issues](https://github.com/HarveyZed/skill-bnote/issues) 提，附上执行的命令、报错原文与 `_meta/validation.json` 的关键片段；贴之前去掉本机路径与个人信息。
- **也可以让你自己的 agent 来改**：`SKILL.md` 是 agent 的执行手册，`references/contracts/` 是写作契约模板，`references/params.md` 是全部参数；把这三处连同报错交给它，通常能自行定位并修改。
- **想认领路线图里的某一项**：在 Issues 里说明你的课程场景和手上那份视频的特征，改动范围通常能收敛到一层。
